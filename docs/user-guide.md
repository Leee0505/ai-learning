# Ticket System 使用说明

## 系统概述

企业级工单管理系统，覆盖 **用户提交 → 客服处理 → 管理员配置与监控** 的完整生命周期。

### 三种角色

| 角色 | 权限范围 | 典型操作 |
|------|---------|---------|
| **普通用户** (ROLE_USER) | 仅自己的工单 | 提交工单、查看进度、回复、关闭确认 |
| **客服** (ROLE_AGENT) | 所有未关闭工单 | 接单、处理、转派、内部备注、知识库检索 |
| **管理员** (ROLE_ADMIN) | 全系统 | 用户管理、SLA 配置、自定义字段、系统监控、数据导出 |

---

## 工单生命周期

```
┌─────────┐     ┌──────────────┐     ┌───────────┐     ┌─────────┐
│  OPEN   │ ──→ │ IN_PROGRESS  │ ──→ │ RESOLVED  │ ──→ │ CLOSED  │
│ 待处理   │     │   处理中      │     │  已解决    │     │  已关闭  │
└─────────┘     └──────────────┘     └───────────┘     └─────────┘
     │                │                    │                │
     提交后           客服接单             客服解决         用户确认
     自动             或管理员分配          填写回复         关闭工单
```

### 状态流转详解

| 阶段 | 触发者 | 操作 | 系统事件 |
|------|--------|------|---------|
| **1. 创建** | 用户 | 填写标题、描述、分类、优先级 → 提交 | `ticket.created` → Agent/Admin 收到 WebSocket 通知 |
| **2. 分配** | Agent/Admin | 工作台点击 "Take" 领取，或在详情页下拉选择 Agent 分配 | `ticket.assigned` → 被分配人收到通知 |
| **3. 处理** | Agent | 添加回复（用户可见）或内部备注（仅 Agent/Admin 可见），可使用模板快速回复 | 回复添加成功 |
| **4. 解决** | Agent | 将状态改为 RESOLVED | 创建者收到通知 |
| **5. 关闭** | 用户 | 确认问题已解决，关闭工单 | 无后续通知 |
| **6. 超时** | 系统 | 每 5 分钟扫描 SLA，超时工单发布告警 | Agent Workbench 显示橙色告警横幅 |

## 各角色操作指南

### 普通用户

#### 1. 登录
- 由管理员创建账号后，使用用户名+密码登录
- 登录后进入 Dashboard，可看到"我的工单统计"
- 右上角铃铛图标显示实时通知

#### 2. 提交工单
- 导航栏 → Tickets → 点击 "New Ticket"
- 填写：
  - **标题**（必填）：简要描述问题
  - **描述**（必填）：详细说明，支持 Markdown 格式
  - **优先级**：LOW / MEDIUM / HIGH / URGENT
  - **分类**：BUG / FEATURE_REQUEST / GENERAL_QUESTION / ACCOUNT_ISSUE / OTHER
  - **自定义字段**：管理员配置的额外字段（如 Environment、Version）
  - **附件**：支持图片、文档、压缩包等，单文件 ≤ 10MB
- 提交后自动进入 OPEN 状态

#### 3. 跟踪进度
- Tickets 列表页查看所有自己的工单
- 支持按状态筛选（OPEN / IN_PROGRESS / RESOLVED / CLOSED）
- 点击工单进入详情页，查看完整的回复时间线和当前状态

#### 4. 回复与关闭
- 在工单详情页底部输入回复内容（支持 Markdown + 附件）
- 客服解决后状态变为 RESOLVED，用户确认无误可关闭
- 关闭后工单归档，不再出现在活跃列表中

### 客服 (Agent)

#### 1. 工作台
- 导航栏 → Workbench
- 顶部三个统计卡片：Pending Queue、My Active、Done Today
- **待接单队列**：展示未分配的 OPEN 工单
- **我的进行中**：已领取的 IN_PROGRESS 工单
- 超时告警横幅：有超时工单时顶部显示橙色警告

#### 2. 接单
- Pending Queue 中点击 **Take** 按钮领取工单
- 工单状态自动变为 IN_PROGRESS，出现在 "My Active" 列表中
- 也可在工单详情页通过 Assign 下拉框分配给其他 Agent

#### 3. 处理工单
- 点击工单进入详情页，可看到：
  - 左侧：工单描述 + 回复时间线
  - 右侧：状态操作、分配、属性编辑、附件管理
- **添加回复**：用户可见，支持 Markdown + 附件 + 引用
- **内部备注**：仅 Agent/Admin 可见，用户不可见（回复区黄色背景标记）
- **使用模板**：编辑区上方可选择常用回复模板快速填充

#### 4. 知识库
- 导航栏 → Knowledge
- 浏览 FAQ 文章，支持 Markdown 渲染
- 搜索关键词快速查找相关答案
- 可在回复中直接引用知识库内容

#### 5. 模板管理
- 导航栏 → Templates
- 创建/编辑/删除常用回复模板
- 按分类组织，在处理工单时快速选择

#### 6. 绩效看板
- 导航栏 → Performance
- 今日完成数、平均处理时长
- 近 7 天完成趋势图

### 管理员 (Admin)

#### 1. 用户管理
- 导航栏 → Admin → Users
- 创建/编辑/删除用户
- 变更角色（User ↔ Agent ↔ Admin）
- 启用/禁用账号：禁用后用户无法登录，已有 JWT 即时失效

#### 2. 工单配置
- 导航栏 → Admin → Config

**自定义字段 (Custom Fields)**
- 定义工单提交表单中的额外字段
- 支持四种类型：Text / Single Select / Number / Date
- 可设置是否必填、是否启用、显示顺序
- 点击字段行可预览在表单中的渲染效果

**SLA 规则 (SLA Rules)**
- 按优先级配置响应时间和解决时间（分钟粒度）
- URGENT / HIGH / MEDIUM / LOW 四个级别
- 跨优先级校验：严格优先级的时限必须小于宽松优先级
- 修改时需确认

#### 3. 系统监控
- 导航栏 → Admin → Monitor
- 实时显示 Kafka、Redis、API 健康状态
- 状态颜色：绿色 HEALTHY / 黄色 WARNING / 红色 CRITICAL
- 支持 10s / 30s / 60s 轮询间隔 + 暂停/恢复
- API P50/P95/P99 延迟分位数

#### 4. 数据导出
- Tickets 列表页 → Export 按钮
- 支持 Excel / CSV 格式
- 可按状态、优先级、分类、关键词筛选后导出

## 实时通知系统

| 事件 | 通知对象 | 通知方式 |
|------|---------|---------|
| 新工单创建 | 所有 Agent + Admin | WebSocket 铃铛 + 列表项 |
| 工单分配 | 被分配的 Agent | WebSocket 铃铛 + 列表项 |
| 工单超时 | 分配的 Agent 或所有 Agent | WebSocket 铃铛 + Workbench 告警横幅 |

- 铃铛红点显示未读数量
- 点击铃铛弹出通知列表，点击通知可跳转到对应工单
- 支持 Mark all read 一键清除红点

---

## SLA 超时机制

| 触发条件 | 超时类型 |
|---------|---------|
| OPEN 状态 + 未分配 + 超过响应时限 | UNASSIGNED_OVERDUE |
| OPEN/IN_PROGRESS 状态 + 已分配 + 超过解决时限 | RESOLUTION_OVERDUE |

- 系统每 5 分钟自动扫描
- 超时工单发布 Kafka 事件 → 通知服务 → WebSocket 推送
- Agent Workbench 顶部显示橙色告警横幅

## 常用工作流

### 场景 1：用户报告 Bug
```
用户提交 Bug 工单 (OPEN)
  → 所有 Agent 收到通知
  → 某 Agent 在 Workbench 点击 Take (IN_PROGRESS)
  → Agent 添加回复询问复现步骤
  → 用户补充信息
  → Agent 定位问题 → 标记 Resolved (RESOLVED)
  → 用户确认 → 关闭 (CLOSED)
```

### 场景 2：管理员分配紧急工单
```
用户提交 URGENT 工单
  → Admin 在 Ticket 详情页 Assign 给指定 Agent
  → Agent 收到通知
  → 4 小时内未响应 → SLA 超时告警
```

### 场景 3：内部协作
```
Agent A 查看工单，不确定如何处理
  → 添加内部备注（Internal Note）："需要 B 协助确认"
  → Agent B 查看内部备注，给出建议
  → Agent A 添加用户可见回复
  → 用户对回复满意 → 关闭工单
```
